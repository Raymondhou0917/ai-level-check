# 隱私、同意與使用邊界

這份專案讀的是一個人**每天工作時打的字**。那裡面有半成品的想法、罵人的話、
臨時查的個人問題、客戶的名字。所以它的預設立場必須是保守的。

如果你只讀一段，讀這一段：

> **這份報告不能單獨作為考績、升遷、解僱或調職的依據。**
> 它是一份觀察，用來幫人看見自己怎麼用 AI，不是拿來排序人的工具。

---

## 三條紅線

### 1. 只能由本人在自己的機器上執行

- 主管不能代跑，HR 不能代跑，IT 不能從遠端掃員工的 `~/.claude/`。
- 要看團隊整體狀況，做法是每個人自己跑、自己決定推不推、推哪一版。
- 任何「幫全公司自動掃描」的部署方式，都違反這一條。
  部署的是工具，不是監控。

### 2. 不排名、不百分位、不自動化決定

- 禁止輸出 PR 值、百分位、名次、「勝過多少比例的用戶」。
  不存在可查證的全球 AI 使用者能力資料庫，這些數字只能是編的。
- 禁止把多個人的等級並列成排行榜。
- 禁止把報告接到任何自動化的人事決定流程。

### 3. 進 git 之前，本人要知道這件事刪不掉

團隊模式的核心機制是「推上 private repo 之後改不掉」——這正是它有公信力的原因，
也正是它危險的原因。

推之前必須確認：

- 本人知道這份報告會進入 git 歷史
- 本人看過要推的那一版
- 敏感度高的內容已經用 `--no-content` 排除

## 資料處理

### 收集階段

`collect.py` 預設就會做這些事，不需要額外設定：

| 處理 | 做了什麼 |
| :-- | :-- |
| 家目錄 | `/Users/xxx` → `~` |
| 金鑰 | `sk-*`、`ghp_*`、`AKIA*`、`xox*-*`、`AIza*`、JWT → `[REDACTED_*]` |
| Email | → `[EMAIL]` |
| 台灣手機號 | → `[PHONE]` |
| 摘錄長度 | 單則上限 400 字，避免整段業務內容外流 |

**去識別化是最低限度，不是保證。** 工作內容本身就可能識別得出人與客戶。
真正敏感的期間，用 `--no-content`。

### 分析階段

- 只處理與工作或事業相關的內容。
- 排除私人生活與客戶機密；混合內容無法安全分離時**直接略過**，
  不提及也不暗示被排除的內容。
- 不推測整體使用頻率、用途百分比、節省時間或實際成效。

### 保存階段

- 證據包（`evidence/`）預設不進 git，見 `.gitignore`。
  進 repo 的是**報告**，不是原始紀錄。
- 報告保存期限由團隊自訂，建議不超過兩年。
- 人離職時，該把他的報告移除。git 歷史刪不掉，
  所以更該在一開始就決定「哪些東西不進去」。

## 給導入這套機制的公司

### 先講清楚再裝

裝之前團隊要先知道四件事，白紙黑字寫下來：

1. **會讀什麼**：AI 對話紀錄，不含私人檔案、瀏覽紀錄、鍵盤側錄。
2. **誰能看**：報告的可見範圍，寫清楚是主管、HR 還是只有本人。
3. **拿來做什麼**：明說「不作為考績單一依據」，並說明實際會怎麼用。
4. **不做什麼**：不排名、不自動決策、不跨人比較。

沒有講清楚就裝在員工電腦上，這套工具會變成監控。它的技術能力做得到，
所以擋住它的只能是制度，不是程式。

### 兩種可行的用法

| 用法 | 做法 | 適合什麼團隊 |
| :-- | :-- | :-- |
| **自願制** | 個人自己跑、自己決定要不要推。公司只看整體分布 | 大多數團隊的起點 |
| **共學制** | 每期一起跑，開會分享各自的分型與一個改善動作，不看等級 | 想把 AI 能力當成共同任務的團隊 |

**不建議的用法**：把等級寫進績效表格、把弱點列進面談紀錄、
拿兩個人的報告並排比較。這幾件事會讓所有人開始為報告表演，
從那天起這份紀錄就沒有參考價值了。

### 分型可以公開，等級不建議

- 分型（`PVSE` 這種）是風格，適合公開、適合當工作坊話題。
- 等級與弱點是個人資料，預設只給本人。

## 給用它來面試的人

請候選人在自己的電腦跑、螢幕分享報告給你看——這比聽他自述「我最近都有在用 AI」準得多。

但不能把面試變成變相監控，也不能變成現場排名：

1. **候選人自己的機器、自己執行。** 面試官不代跑，不要求把 `~/.claude/` 或 `~/.codex/` 打包寄來。
2. **用螢幕分享看報告，不要把 HTML 留下來當人事資料，也不要截圖。** 裡面可能有現職客戶、未公開產品、跟這次應徵無關的內容。看到與職缺無關的機密，當場請對方切走。
3. **建議用 `--no-content`，或先讓候選人自己看過案例摘錄再分享。**
4. **這份報告不能單獨作為錄用或淘汰依據。** 只用網頁版、公司筆電不給裝、或紀錄落在還沒支援的工具上的人，會被系統性看低——那是來源缺口，不是能力差。
5. **不要在連續面試之後把等級拿來排序。** 分型可以當話題，LV2／LV3／LV4 不要在心裡排成名次。

這五條跟上面的三條紅線同一件事：工具做得到監控與排名，擋住它的是你怎麼用。

沒有這麼複雜。你自己跑、自己看，愛給誰看就給誰看。

唯一提醒：如果你要把報告貼到社群，先用 `--no-content` 跑一次，
或者自己逐條看過案例摘錄——裡面可能有客戶名字、專案代號、還沒公開的產品。
