# 報告書規範

報告分兩層：**總覽頁**（一頁看懂綜合能力）＋**詳細分析**（六節，給想深入的人）。

視覺設計服務於閱讀、比較與理解。**排版不新增分數、結論或案例。**

---

## 總覽頁（報告第一頁）

依序呈現六塊，順序不變：

### 1. 參考資料範圍

2–4 句，放在等級與結論**之前**。交代讀到哪些紀錄、涵蓋期間、缺哪些、這次能判斷什麼。

### 2. 綜合評級，以及一眼看懂的三欄

單一整體等級（`LVn` 或 `LVn＋`）。

- 資料只支持部分範圍時寫「目前可確認至 LVn」
- 不足以支持穩定分級時寫「無法定級」
- 加一句最主要的已確認落差，或尚缺的評估證據——**兩者要分清楚**
- 等級名稱與下一句解釋，要用主管／HR 不必先懂 AI 術語也讀得懂的白話

緊接在評級下方，用三欄（窄螢幕改直排）寫：

1. **擅長什麼**（最多四句，每句附案例編號）
2. **目前沒做好什麼**（最多兩句；沒有已確認弱點就寫「本次資料不足以確認弱點」）
3. **下一步做什麼、怎樣算完成**（只寫一件最先要做的事）

這三欄是給本人與主管的第一屏，不能被等級量表或分型擠到後面。

### 3. 等級量表

完整列出 LV0–LV5 六個等級的名稱與一句定義，標出本次可確認的等級。
無法定級時明示未標定。

讀者不需要回頭查這份 skill 就要看得懂每一級的意思。

### 4. 等級說明

- 說明符合目前等級的行為證據
- 未達 LV5 時，說明下一級所缺的行為或證據。**系統驗證未測、窗口內沒碰到故障，都不得寫成未達 LV5。**
- 已達 LV5 時，列現有不足與維護方向，**不虛構下一級**
- 另起一行「系統驗證狀態」，摘要哪些已驗證、哪些尚未確認
  （完整四項放在詳細分析第 4 節）

### 5. 人物志分型

分型代號、稱號、一句話，以及「判給這一型的依據是哪個案例」。

**同一區塊內必須寫上「分型是風格不是分數」。**

### 6. 精華摘要

從詳細分析的前五節各挑一條有證據支持的重要發現，每條一句話並附案例編號：

| 來源 | 挑什麼 |
| :-- | :-- |
| 綱要瀏覽表 | 最能代表日常使用方式的一項觀察 |
| 優先改善事項 | 最優先處理的一項不足 |
| AI 核心能力表 | 最有證據支持的一項強項 |
| 工作系統對照 | 最關鍵的一項理解證據或缺口 |
| 制度化潛力 | 最值得固化的一個做法 |

沒有證據的項目寫「資料不足，無法判斷」或直接省略。
**不為了填滿格式而補出優點、不足或可固化做法。**

### 結尾一句

「完整證據與判斷依據見後方詳細分析。」

## 詳細分析（六節，順序不變）

### 1. 綱要瀏覽表

欄位：`檢查項目｜觀察到的做法｜依據哪個案例｜出現幾次或是否持續｜已確認的不足｜這個判斷有多少依據`

固定七列：

1. 日常主要用途
2. 核心能力掌握
3. 提問迭代方式
4. 個人應用面向（不含私人生活）
5. 制度化潛力
6. 工作系統理解
7. AI 對事業背景的掌握

未觀察的項目照[判定量表](evidence-rules.md#四種判定量表)標示，不用正面描述填滿。

表後必須有一個預設收合的「本次讀到的工作實例」折疊區塊：用**表格**列出每個案例（編號、這件工作、誰在做、入口、日期），本人操作與系統自動跑分組，不用列點。
讀者不必先懂「案例 3」才能看懂綱要表。重要判斷仍寫在表裡，摘錄可再收一層。

### 2. 優先改善事項

放在綱要表後面，直接呈現最重要的問題。最多完整展開三項，其他已確認的重要不足簡列——
**不因為數量限制而隱藏高影響問題。**

每項包含（最多五個精簡要點）：

- 具體不足與分類
- 原始證據：本人說了、做了或遺漏了什麼
- 判斷理由：為什麼該情境需要不同做法；有哪些替代解釋
- 影響與優先級：分開標示已觀察影響與可能影響
- 下次怎麼做、怎樣算有改善

證據不足以確認弱點時，明確寫「本次資料不足以確認弱點」並列出無法判斷的能力，
**不要寫「整體表現良好」代替。**

### 3. AI 核心能力表

欄位：`檢查哪項能力｜目前做到什麼程度｜依據哪個案例｜做得好的地方｜需要改善的地方`

依[七項核心能力](evidence-rules.md#七項核心能力)逐項呈現。
優勢最多兩項摘要，不強迫找足；不足引用前一節，不重複展開。

### 4. 工作系統與組織強度對照

標題固定用這句，不要改成「工作系統長什麼樣子」。
本節**必須**依這個順序出現；後面的多棲圖與齒輪是附加，不能拿掉前兩塊來換它們。

**4a. 組織強度對照表**（原版 B 節，不可省略）

欄位：`哪項工作｜已理解哪些要求｜依據哪份資料或案例｜還有哪些問題｜這個判斷有多少依據`

最多三個主題。判準見 [工作系統與組織強度](evidence-rules.md#工作系統與組織強度)。
無法讀取必要來源時明確標示未完成交叉對照，不用通用職場常識代替。
「已理解哪些要求」要列具體要求與支持該判斷的行為，不能只填「良好」。

**4b. AI 對事業背景的掌握**（原版 C 節，獨立小標，不可省略）

最多三句。評的是對話裡的 AI，不是本人。
沒讀到事業資料也要出現這塊，寫「尚未觀察」並說明缺哪種來源。
判準見 [AI 對本人事業背景的掌握](evidence-rules.md#ai-對本人事業背景的掌握)。

**4c. 本機才看得到的系統樣貌**（貼上模式可寫「這次看不到」）

多棲圖、自動化齒輪。這是本專案加的，放在原版兩塊**之後**。

**4d. 系統驗證狀態**

`驗證項目｜目前狀態｜依據與結果或缺少的資料`，四項逐列。
尚無可辨識的系統案例時，四項都標「尚未驗證：本次未取得可辨識的系統案例」，
不要求為了檢核額外建置系統。

### 5. 值得保留與制度化潛力

標題固定用這句，不要改成「值得留下的做法」。

欄位：`值得保留的做法｜目前怎麼用｜以後可以怎麼用｜下一步先做什麼`

最多三項，沒有證據就整節省略。

「目前怎麼用」與「以後可以怎麼用」必須寫[應用成熟度](evidence-rules.md#應用成熟度)全名：
一次性用法／日常輔助／可複用資產／制度化流程。
可以在全名後面補一句說明，但不能只用「已經在用」代替。

「下一步」只選最先需要的一個動作。建議維持現況時說明理由，
**不為了升級硬加工作。**

### 6. 最後結論

依序只寫三件事：

1. 最優先處理的已確認不足；沒有的話，說明最重要的判斷限制
2. 下一次同類工作可直接採用的一個改善動作；提不出就明說
3. 一個有證據支持、值得保留或固化的做法；沒有就省略

必要時附最多三項「可自願校正的判斷」，只列會影響能力描述或原因歸屬的事項，
**不要求回覆。**

## HTML 製作

### 交付方式

- 單一檔案、內嵌樣式、系統字型，圖表用內嵌 SVG
- 不依賴外部套件、字型或圖片
- 不自動對外傳送或公開發布
- 對話裡只附簡短總覽與檔案連結，**不貼大段原始碼**
- 頁尾用編輯落款，不放推銷卡片或按鈕膠囊。固定兩條文字連結：開源專案網址（尚未公開就寫預留網址）、品牌學習站 `https://ai.lifehacker.tw/`。本報告不是考績工具的聲明放在同一段。

長報告先建立共用版型與章節結構，再分章寫入同一份檔案，
最後核對目錄、章節、案例、圖表與結尾是否完整。

產生失敗時，先試分段製作或簡化裝飾與互動，保留完整分析。
仍無法完成或平台不支援檔案時，交付完整文字報告並說明**實際卡在哪一步**。
只有確認文字分析完整、問題僅發生在排版時，才能說分析內容不受影響。
**不要假裝執行過。**

### 版面

1. **首頁就是綱要頁**，不另做只有大標題的封面，也不塞入完整分析。
   以一張直式報告頁為編排目標，內容超出時自然續頁，不縮字、不裁切。
2. 網頁開啟時先顯示綱要，後續章節依閱讀順序往下展開。
   **長報告（六節詳細分析）用左側浮動目錄**，規格對齊 `report-page` 的 TOC Rail：
   `position:fixed; left:24px; top:100px; width:156px`，等寬編號、無色塊、無粗框。
   主欄 `.wrap` 維持 `margin:0 auto`，**不被目錄往右擠**。
   螢幕窄於 1400px 時目錄改成右下角 `☰ 章節目錄` 按鈕。列印時隱藏目錄。
3. 每章先呈現主要發現，再用圖表整理關係，接著說明案例、證據與判斷理由。
   重要分析預設展開；只有較長的原始摘錄可以收合。
4. 編輯式報告設計：一致的欄線、頁邊距、文字層級、章節編號、圖說與頁尾。
   用排版、比例與留白形成層次，**避免整份報告變成重複的小卡片堆疊**。

### 配色與字級

- 白或淺暖灰底、深墨色文字、一個低飽和主色
- 少量暖色提示需處理事項，灰色搭配文字標示資料不足
- 標題可用系統襯線字體，內文用清晰無襯線字體
- 避免裝飾動畫、大面積漸層與無意義圖示
- 桌面正文至少 16px、行距 1.6–1.8；主欄 `.wrap` 寬度 **1000px**（內文跟隨主欄，不再另限 38em）
- 標題、正文、註解至少三個明確層級
- 手機不截字、不縮小字體、不讓整頁左右滑動
- **HTML 不顯示 Markdown 星號**，用字重與語意標籤

### 圖表

1. **圖表要回答具體問題。** 評估方要一眼看懂時，優先這幾種（都用內嵌 SVG、報告既有配色與系統字型，不引入外部字型）：
   - **誰在做事**：本人／系統／小幫手的數量對照（已有長條）。
   - **工作量（僅供參考）**：本人對話則數、打出去的訊息數、平均每則幾則；有 token 才列輸出。必須附這句：最好的 AI 工作者是用最少的訊息數跟最少的 token 達到一樣的成果；但因為每個人對工作成果好的標準不同，這個數字無法直接拿來評估，僅供參考。
   - **多棲**：入口如何接到同一份規則（架構圖，取代 ASCII）。
   - **例外與回寫**：信件只進草稿、本人看完才寄（流程圖）。
   - **自動化齒輪**：五格狀態帶，有看到／這段沒看到；**不印分數、不畫雷達**。
   - **人物志四軸**：2×2 格，不是雷達圖。
   案例清單用表格，不用列點、不用十張一樣大的卡片。
   沒有適合的圖就保留文字，不強迫每章有圖。
2. 六級量表用六個簡短項目或階梯式文字圖，標示本次可確認的等級及其限制。
   無法定級時不標示位置。
   **能力、成熟度與證據強度是不同概念，不換算成數字後混畫。**
3. 只有來源提供可核對的數值、單位與範圍時，才使用長條圖、折線圖，並註明來源與計算方式。
   **不編造能力分數、百分位或進度；不用雷達圖、儀表盤暗示未經驗證的量化結果。**
4. 每張圖附清楚標題、必要圖例、一句閱讀結論與案例來源。
   所有狀態同時用文字呈現，不能只靠顏色；圖中文字要可選取。
   關係或建議來自推論時明確標示，不畫成已確認的因果。
5. 每項改善建議完整呈現觀察、依據與原因、影響、下一步及完成標準，
   保留問題分類、優先級與證據強度。
   **不因為圖表化而省略反例、重要不足、資料缺口或未實測限制。**

### 完成檢查

- 先核對分析內容與 HTML 的章節、案例及結論一致，再檢查畫面。
  圖表不能代替其背後的完整說明。
- 有預覽工具時，實際檢查桌面與手機版的首頁層次、長文換行、表格、圖說、目錄及案例連結。
  沒有工具就明示未做畫面檢查，**不要把「產生了檔案」當成「版面正常」**。
- 列印樣式採 A4 直式，綱要後另起頁，後續章節自然分頁並保留頁邊距。
  避免標題單獨留在頁尾，或圖說與圖分離。
  列印時展開證據、隱藏操作按鈕，取消固定高度及捲動容器。
- 互動元件要能用鍵盤操作。
