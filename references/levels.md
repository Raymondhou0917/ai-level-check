# AI 使用量表 LV0–LV5

這是**本專案內部定義的行為描述**，不是任何全球排名或百分位。
較高的等級代表已展現更多複用、交接與系統運作的能力，不代表每一項能力都比較強，
也不要求本來就沒有複用需求的工作為了升級而自動化。

---

## 六個等級

### LV0　問答靠人品

在確實需要補條件、查核或修正的任務中，有**直接證據**顯示本人沒處理這些需要就採用了答案，
成果能不能用缺少判斷依據。

不算 LV0 的情況：

- 簡單的一問一答，或一次就完成的任務
- 資料不足，只是沒讀到修正紀錄
- 前文已經提供過條件，這一輪不必重講

> **LV0 不是資料不足時的預設值。** 掃不到可歸屬本人的紀錄，寫「無法定級」。

### LV1　換句話重問

能察覺明顯錯誤，並換個說法或多問幾次把任務推進；可見案例裡的修正主要靠反覆嘗試，
還沒穩定展現「指出具體問題」的做法。

未觀察到精準修正，只能寫成未觀察到，不能寫成本人不會。

### LV2　單點式應用

能穩定用 AI 完成單一類任務（寫作、摘要、查資料、改程式），並判斷答案能不能用。

「是否已能精準指出問題並有效修正」另依需要修正的案例判斷；沒有這類案例時保留未知。

### LV3　精準下指令

能給背景、範圍與完成標準；AI 答錯時能指出具體問題，讓下一輪真正修正，
把單次任務推進到可用成果。

判準在「下一輪有沒有真的解決」，不在提示詞寫得多長。

### LV4　模組化使用

能把有效做法固定成模板、指示頁、Skill 或自動化代理，**啟用前會實際測試**，
成果別人看得懂、接得手。

需要實作證據：看得到那份模板或腳本的內容，且看得到它被再次使用。

### LV5　系統級營運

能把本人、AI 與必要協作者的分工、完成標準、例外處理與維護方式，整合成實際運作的工作系統，
並把執行結果與修正**寫回**可持續使用的流程。

必要條件，缺一不可：

- 對應到具體案例中的分工、完成標準、例外處理、維護與流程回寫
- 有跨案例，或同一系統多次獨立執行的紀錄
- 同一次任務的多輪對話**不算**多次執行

單人事業同樣適用：沒有同事不是問題，有沒有等效機制才是問題。

## 證據要求

| 等級 | 主要看什麼 | 可接受的證據 |
| :-- | :-- | :-- |
| LV0–LV3 | 問答行為 | 對話紀錄本身就夠 |
| LV4 | 實作過程與結果 | 模板／Skill／腳本的內容，加上被再次使用的紀錄 |
| LV5 | 系統運作與回寫 | 多次獨立執行紀錄、例外處理紀錄、維護欄位、流程被改寫的痕跡 |

證據依內容判斷，不限定存放位置。歷史對話裡實際讀得到的工具執行結果、成果內容、
檢查與修正紀錄，可以直接當證據，不能只因為「證據來自對話」就排除。

但是：

- 只有連結而沒讀到內容，仍然只是線索
- 單純自述、AI 宣稱完成、設計構想，都不算實作證據
- 這份 skill 本身、現成模板、模板裡預先寫好的要求，不是本人能力的直接證據
- 先前 AI 生成的能力報告不能取代原始證據

## 對照證據包欄位

`collect.py` 產出的 `summary.json` 對應到哪一級，不是換算，是**去哪裡找線索**。
數字本身永遠不能直接定級，一定要回去讀 `cases.md` 的案例原文。

| 證據包欄位 | 可以支持什麼 | 明確不能支持什麼 |
| :-- | :-- | :-- |
| `session_split.human` | 這個期間有沒有可分析的本人紀錄 | 數量多寡不代表能力 |
| `behaviour_signals.spec_turns` | 有交辦條件的候選案例在哪 | 出現過不等於 LV3，要看那次有沒有推進到可用成果 |
| `behaviour_signals.correction_turns` | 有修正行為的候選案例在哪 | 分不出「換句話重問」（LV1）與「指出具體問題」（LV3），必須讀原文 |
| `behaviour_signals.verify_commands` | 查核有沒有真的執行過 | 跑過測試不等於查核到位 |
| `artifacts.durable_writes` | LV4 的候選證據：寫到 SKILL、scripts、workflows、設定檔 | 寫過一次不等於被複用，要找到再次使用的紀錄 |
| `automation_evidence.sessions` | LV4–LV5 的候選證據：本人不在場時系統跑過 | 跑過不等於跑得對，更不等於有維護與交接 |
| `automation_gears.observed` | LV4 的「固化成代理」具體化；兩顆以上咬合是 LV5 的常見形態 | **覆蓋度不是分數**。沒那個需求就不該用那顆齒輪；未觀察到只是期間快照，不等於不會。見 [automation-gears.md](automation-gears.md) |
| `automation_evidence.subagent_sessions` | 有沒有分工的線索 | 派過子代理不等於分工設計良好 |
| `human_usage.unique_tools` | 描述樣本 | **不得**當成能力指標 |
| `sample_description_only.*` | 描述樣本 | **不得**當成能力指標 |

## 定級規則

1. 只依已有證據的行為，逐項列出符合該級的行為並附案例編號。
2. 下一級的條件分成「已確認尚未做到」與「尚無證據可判斷」，不可混為一談。
   各級描述裡的不足，不能只因為沒讀到紀錄就成立。
3. 綜合評級＝在本次資料範圍內，行為門檻有**穩定證據**支持的最高單一等級。
   不要求高等級者同時具備低等級描述裡的不足。
4. 已有部分下一級的正面證據時可標 `LVn＋`；**不能只因為缺資料就加 `＋`**。
5. 較高級只有單次或零星證據時不升級，另外列出已觀察到的行為。
6. 較高級因缺少必要行為或實作證據而無法評估時，寫
   「目前可確認至 LVn；較高等級尚未評估」，不解讀成能力上限。
   單純缺少四項系統驗證紀錄，不使用這條規則限制等級。
7. 個別不足另列，**不平均計分**。
8. 若直接證據否定所判等級的必要條件，重新檢查定級；
   不能用一句「還有落差」保住一個不成立的等級。

## 外部框架對照

要對照公開框架（企業 AI 成熟度模型、各家 AI literacy 框架）時：

- 先查證框架原文的分級定義，只用**行為特徵**對照，逐項說明本人已有證據的行為
  符合哪一級的哪些定義
- 一律標示「此為框架對照，非實測百分位」
- **禁止**輸出 PR 值、百分位、名次、「勝過多少比例用戶」——
  不存在可查證的全球 AI 使用者能力資料庫
- 查無適用且可查證的公開框架時，明寫「查無可對照框架」，不得用推估數字代替

這一段屬於框架對照而非排名，不牴觸[公平判斷](evidence-rules.md#公平判斷)裡
禁止生成排名的規則。
