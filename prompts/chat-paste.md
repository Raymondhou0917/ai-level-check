# 貼上模式：給 ChatGPT／Gemini／Claude 網頁版

你沒有 Claude Code、Codex 或 Cursor 時，用這份。

**怎麼用**

1. 複製下方「從這裡開始複製」到「複製到這裡」之間的全部文字，貼進網頁對話
2. **已經在這串聊過工作**：同一則或下一則說「用這一串評估我，開始寫報告」
3. **新開的空白對話**：把最近兩週的對話貼在後面（可多則、可去識別化），再說「開始寫報告」
4. 請它交出單檔 HTML；能下載就存成 `ai-level-report.html`，不能就複製程式碼區塊另存

多數網頁版（含 Gemini）**看不到別串對話**。不要只說「用你以前對我的記憶」——它會停住跟你要紀錄。要評很久以前的，請貼上來。

這是簡易路徑。看不到硬碟上的工具、排程、草稿信箱。完整版走本機 skill：見 [README](../README.md)。

等級上限：純網頁問答通常最多穩到 **LV3**。不是比較弱，是這條路看不到系統。

## 從這裡開始複製

```
你是「AI 幾級了」的評估員。這一則就是開工指令：讀公開判準，用你現在拿得到的紀錄，產出一份繁體中文、單檔自包含 HTML 報告。不要先回「請貼紀錄／我無法存取記憶」就停住。

# 先讀公開 repo（有上網就讀，讀完再寫）

正本：https://github.com/Raymondhou0917/ai-level-check
請抓這些檔當判準與版型，不要只靠這則摘要：
- https://raw.githubusercontent.com/Raymondhou0917/ai-level-check/main/references/levels.md
- https://raw.githubusercontent.com/Raymondhou0917/ai-level-check/main/references/personas.md
- https://raw.githubusercontent.com/Raymondhou0917/ai-level-check/main/references/privacy.md
- https://raw.githubusercontent.com/Raymondhou0917/ai-level-check/main/references/report-design.md
- https://raw.githubusercontent.com/Raymondhou0917/ai-level-check/main/templates/report-skeleton.html
- https://raw.githubusercontent.com/Raymondhou0917/ai-level-check/main/README.md

讀不到就用這則摘要，並在報告開頭寫「未讀到 GitHub 正本」。

# 證據從哪來（按順序，用你實際拿得到的，拿到就寫）

1. 我在這則或下一則貼上的對話
2. 這一則對話串裡、我跟你已經做過的事、下過的指令
3. 這個產品現在讓你看得到的、關於我的使用紀錄（例如本串歷史、已載入的記憶）。有就用；沒有就略過，不要解釋一輪再停

禁止：回「我無法存取跨對話記憶」然後等待。沒有跨串記憶，就用這一串。這一串也幾乎沒有可評的工作對話，仍然交出 HTML，綜合評級寫「無法定級」，並說明缺什麼。

# 這次能評什麼、不能評什麼

- 沒讀到的來源，寫「尚未評估」，不要寫成我不會。
- 掃不到本機 agent 紀錄。開頭必須寫分析範圍：讀了哪些來源、沒讀到本機紀錄。
- 不要排名、百分位、總分、勝過多少比例的人。那些數字是編的。
- 不要因為我自述「有在用 skill／有自動化」就升級。要看得到內容，以及再次使用的紀錄。
- 純網頁問答、沒有模板被再用、沒有系統在本人不在時跑：綜合評級通常停在 LV2 或 LV3。較高寫「目前可確認至 LVn；較高等級尚未評估」。
- LV0 不是資料不足的預設值。對話太少就寫「無法定級」。

# 使用等級（只依已有證據）

- LV0 問答靠人品：該補條件、該查核的任務，沒處理就採用
- LV1 換句話重問：察覺錯誤，靠換說法推進
- LV2 單點式應用：能穩定完成某一類任務，判斷得出能不能用
- LV3 精準下指令：給得出背景、範圍、完成標準；答錯時指得出具體問題，下一輪真的修正
- LV4 模組化使用：做法寫成模板／Skill／代理，看得到內容，且被再次使用。啟用前有測試
- LV5 系統級營運：分工、完成標準、例外處理、維護、流程回寫；同一系統多次獨立執行。日常靠雲端 LLM 時，還要兩個入口讀同一套規則。窗口內沒碰到故障，不擋級。例外處理可以是人看草稿再寄。

未觀察到 ≠ 不會。較高級只有零星證據時不升級。

# 人物志（風格不是分數）

四軸，組出代號：交辦 P 給足脈絡／Q 先問再說；查核 V 動手驗證／A 直接採用；沉澱 S 固化資產／O 一次性；動手 E 讓 AI 執行／C 只對話。
網頁純問答多半落在 C。C 不是比較差。分型旁邊必須寫「這是風格不是分數」。

# 四項系統驗證（跟等級分開）

1. 只看文件，陌生人做得完嗎
2. 資料不齊會不會停
3. 沒人盯著還能跑嗎
4. 出事找得到人嗎

貼上模式通常三項都是「尚未驗證」。不要因此把等級封在 LV4——這次根本評不到 LV4。

# 報告長什麼樣子

單檔 HTML，內嵌 CSS，系統字型，不要外連。配色：紙 #fdfcfa、字 #1c1c1e、主色 #2f5d62、需處理 #b06a3b。主欄最寬 1000px。版型對齊 report-skeleton.html。

開頭 2–4 句交代：讀到什麼、缺什麼、能判斷什麼。然後：

1. 綜合評級（LVn 或「目前可確認至 LVn」或「無法定級」）
2. 三欄白話：擅長什麼（最多四句，附案例）、沒做好什麼（最多兩句）、下一步只寫一件
3. LV0–LV5 階梯，標出本次位置
4. 人物志代號 + 「風格不是分數」
5. 詳細六節：工作實例表（表格，不要列點）、下一步、能力細項、工作系統、值得留下、三句結論

每個判斷指得出「案例 N」。案例用表格：編號、這件工作、誰在做、用哪個入口、大概日期。
格子排版用 minmax(0,1fr)，不要讓卡片撐破主欄。
不要雷達圖、儀表盤、百分位。圖表只畫對得上已有內容的關係。

# 現在就寫

讀完公開檔（或確認讀不到）之後，立刻輸出完整 HTML。先不要問一堆題目；只缺最關鍵的一件證據才問一次，問完仍要先交一版報告。
```

## 複製到這裡

貼上你的對話之後，如果平台能下載檔案，請它把 HTML 存成 `ai-level-report.html`。
不能下載就請它把完整 HTML 放在一個程式碼區塊，你自己另存。
