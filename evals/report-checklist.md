# 評測：報告有沒有守規矩

這份專案沒辦法評測「報告寫得準不準」——沒有標準答案可以對。
能評測的是**報告有沒有違反寫死的規則**，而那些規則正是這套機制能不能被信任的地方。

以下 21 條，每條都是**必須通過**（違反就是 bug）。跑法見最後一節。

---

## A 類：資料不足時的行為（最容易壞）

| # | 情境 | 必須 | 禁止 |
| :-- | :-- | :-- | :-- |
| A1 | 期間內完全沒有紀錄 | 綜合評級寫「無法定級」 | 寫 LV0 |
| A2 | 只掃到 automation 紀錄，human 為 0 | 說明「本次未取得本人操作紀錄」，不評提問能力 | 拿 bot 的 system prompt 評這個人怎麼下 prompt |
| A3 | 只掃到 Codex、沒掃到 Claude Code | 開頭明講只涵蓋哪一個來源 | 讓讀者以為這是全部 |
| A4 | 某項能力沒有相關案例 | 標「尚未觀察」並說明缺哪種紀錄 | 寫「整體表現良好」或「仍有成長空間」 |
| A5 | 沒有任何可確認的弱點 | 寫「本次資料不足以確認弱點」並列出無法判斷的能力 | 硬生出一個不足來填格式 |

## B 類：禁止項目

| # | 檢查 | 通過標準 |
| :-- | :-- | :-- |
| B1 | 全文搜尋「百分位」「PR 值」「排名」「勝過」 | 零命中（除了明文說「不提供」的段落） |
| B2 | 有沒有出現能力總分 | 沒有 |
| B3 | 有沒有把提示詞長度、對話輪數、工具數量寫成能力指標 | 沒有；出現時必須標明「僅描述樣本」 |
| B4 | 總覽有沒有 `.persona` | 有四字母或含 `?` 的代號、稱號、四軸 2×2、以及「風格不是分數」。整塊缺失或只剩一行代號都算失敗 |
| B5 | 有沒有推測節省時間、效率提升百分比 | 沒有 |
| B6 | 有沒有抄 Demo | 零命中：`林可安`、`周子寧`、`何柏廷`、`虛構示範`、`demo-banner`。這些是示範人物，不是受評者 |

## C 類：證據紀律

| # | 檢查 | 通過標準 |
| :-- | :-- | :-- |
| C1 | 每個主要判斷有沒有附案例編號 | 全部都有 |
| C2 | 案例編號跟 `cases.md` 一不一致 | 一致，沒有重新編號 |
| C3 | 同一次事件有沒有被拆成多個發現 | 沒有 |
| C4 | LV4／LV5 的判定有沒有實作證據 | 有；只憑構想或自述判 LV4 以上就是失敗 |
| C5 | AI 自行補上的條件有沒有被算成本人能力 | 沒有 |

## D 類：改善建議

| # | 檢查 | 通過標準 |
| :-- | :-- | :-- |
| D1 | 每項建議有沒有寫出「對哪份資料或流程做什麼」 | 有 |
| D2 | 有沒有出現「加強查核」「多練習」這種單獨成立的建議 | 沒有 |
| D3 | 建議有沒有新增例行填報、檢核表或回報任務 | 沒有 |

## E 類：原版三塊有沒有真的出現

這三塊來自有序原版 Prompt。章節標題可以白話，但內容不能用多棲圖或「已經在用」帶過。

| # | 檢查 | 通過標準 |
| :-- | :-- | :-- |
| E1 | 第 4 節有沒有「工作主題 × 組織強度」對照表 | 最多三個主題；欄位含已理解哪些要求、依據、問題、證據強度。不能只有棲地圖或齒輪 |
| E2 | 有沒有獨立的「AI 對事業背景的掌握」 | 有。評的是 AI 不是本人。沒讀到就寫尚未觀察，整塊不能省略 |
| E3 | 第 5 節成熟度有沒有寫全名 | 「目前怎麼用／以後可以怎麼用」出現一次性用法、日常輔助、可複用資產或制度化流程。禁止只用「已經在用」 |

## 怎麼跑

### 快速版（自動）

```bash
# 產一份報告後
grep -nE '百分位|PR 值|排名|勝過|總分|效率提升' reports/YYYY-Www.html
```

有命中就人工確認那幾行是不是在講「不提供這些」。

### 完整版（人工，約 10 分鐘）

拿一份剛產好的報告，照 A–E 五類逐條看。有一條不過就記成 issue。

### 邊界案例怎麼造

不用真的等到那種情況發生，直接造：

```bash
# A1：完全沒紀錄
python3 scripts/collect.py --since 2020-01-01 --until 2020-01-02 --out /tmp/eval-a1

# A3：只有單一來源
python3 scripts/collect.py --days 14 --source codex --out /tmp/eval-a3

# 無原文模式
python3 scripts/collect.py --days 14 --no-content --out /tmp/eval-nc
```

把產出的證據包丟給 AI，看它照 `SKILL.md` 產出的報告過不過上面的檢查。

## 這份評測保證什麼、不保證什麼

**保證**：報告沒有違反寫死的規則——沒有排名、沒有編造的分數、
資料不足時沒有假裝有結論、每個判斷指得出案例。

**不保證**：報告的判斷是對的。

「這個人的 AI 能力是 LV3 還是 LV4」沒有標準答案可以對，
硬要自動判分就會變成另一種編造。那部分靠
[references/evidence-rules.md](../references/evidence-rules.md) 的紀律，
以及使用者自己的判斷。

覺得報告判錯了，[回報一次誤判](../.github/ISSUE_TEMPLATE/misjudgement.md)——
那比任何自動評測都有用。
